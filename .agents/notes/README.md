# 决策与踩坑笔记

记录本仓库的重要技术决策、架构变更、踩坑经验与上游分歧。

## 记录规则

### 触发条件（满足任一即写）
1. **契约变更**：SQLite schema、索引格式、配置格式、对外 API 契约。
2. **跨界影响**：跨两个以上模块或跨仓库联动。
3. **方案否决**：否决了看似更优的备选方案。
4. **临时处置**：临时降级、workaround、特判代码。
5. **分歧维护**：与 upstream（上游）的故意分歧。
6. **性能调优**：关键性能参数取值原因与权衡。

### 豁免清单
- 常规版本 bump
- 纯文案调整
- 行为不变的单文件 bug 修复
- 小版本依赖升级
- 纯测试用例补充

> **注意**：触发优先于豁免。例如单文件修改但包含 workaround/特判时，必须记录笔记。

## 编写与管理规范
- **模板**：参考 [_template.md](_template.md)。
- **命名**：`YYYYMMDD-slug.md`（如 `20260917-fork-delta.md`）。
- **不可变性**：旧笔记原则上不改写；状态废弃时仅修改 frontmatter 中的 `status: superseded` 并补充 `superseded_by` 链接。
- **索引刷新**：添加或修改笔记后，运行 `scripts/notes-index.sh` 刷新本地索引 `INDEX.md`（该文件已在 `.gitignore` 中忽略，不入 git）。
本目录用于沉淀核心技术决策、架构变更、排障踩坑及与 upstream 分歧记录。

## 触发条件（满足任一即写）

1. **Schema / 格式 / 契约变更**：SQLite schema、索引格式、配置格式、对外 API / IPC 契约调整。
2. **跨模块或跨仓库联动**：跨两个以上业务模块（如 `features/terminal` 与 `conduit_vt`）或涉及跨仓库协调。
3. **否决看似更优方案**：经过评估或尝试后放弃的方案（须记录原因防止后来者重踩）。
4. **临时降级 / Workaround / 特判**：为绕过平台、框架或依赖库 Bug 所做的非标准实现。
5. **与 upstream 的故意分歧**：相对上游 `gwitko/Conduit` 的定制演进（如自定义 `conduit_vt` 注入、自定义 CI/发布链）。
6. **性能取值原因**：关键缓冲区大小、超时时长、并发数等性能关键常数的确立依据。

## 豁免清单

以下改动若不满足上述任一触发条件，可不记录笔记：
- 版本 bump 与发布元数据修改
- 纯文案或国际化文本调整
- 行为不变的单文件 bug 修复与重构
- 语义化小版本依赖安全升级
- 纯补充或修复单测

> **注意**：触发优先于豁免。若单文件改动属于 workaround 或特判，必须记录。

## 规范与流程

- **命名规范**：`YYYYMMDD-slug.md`（如 `20260917-conduit-vt-git-override.md`）。
- **模板参考**：新建笔记请参考 [_template.md](_template.md)。
- **不可变原则**：历史笔记落盘后只加 `superseded` 状态及链接，禁止改写或删除历史决策内容。
- **刷新索引**：新增或修改笔记后，运行 `scripts/notes-index.sh` 自动生成本地 `INDEX.md`（该文件已被 gitignore）。
